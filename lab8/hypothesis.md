# Карточка проверяемой гипотезы для ЛР-9 (`hypothesis.md`)

## 1. Формулировка гипотезы (`H1`)
**H1:** детерминированная замена заранее заданных предметных синонимов и близких формулировок каноническими словами из словаря проекта (например: `киберпанк -> неон`, `ливень -> дождь`, `мегаполис -> ночной город`, `мгла -> туман`, `хвойный бор -> сосновый лес`, `заря -> рассвет`, `железобетон -> бетон`, `барханы -> дюны`, `океанское дно -> подводный мир`, `рифы -> кораллы`, `грампластинки -> винил`) **перед** тем же расчётом TF-IDF повысит средний `NDCG@3` на `validation` минимум на **`+0.20`** (с `0.5000` до **`>= 0.7000`**, достигая порога alpha-версии) без снижения защитной метрики `Recall@3` (не ниже baseline `0.3611`) и при строгом нуле карточек без допуска в выдаче.

## 2. Связь с анализом ошибок
* В `error_taxonomy.md` показано, что на знакомой лексике (`literal`, 6 запросов) baseline уже даёт высокий результат (`NDCG@3 = 0.9073`, `Recall@3 = 0.6667`), тогда как все провалы сосредоточены в сегменте `paraphrase` (`6/12` запросов, `NDCG@3 = 0.0927`) из-за отсутствия синонимов в словаре `train` (`OOV`).
* Поэтому первым шагом проверяется не усложнение модели ранжирования, а нормализация терминов запроса на входе.

## 3. Что меняем и что фиксируем (чистота эксперимента)
* **Единственное изменение:** добавляется шаг замены известных синонимов на канонические термины при обработке токенов запроса перед векторизацией TF-IDF.
* **Фиксированные условия (остаются без изменений):**
  * Версия и состав набора данных (`1.0-scene-refs`, `12` карточек `train` + `12` карточек `validation`).
  * Разбиение `train` / `validation` и расчёт `IDF` строго по `train`.
  * Исходные `12` запросов `Q01`–`Q12` и их разметка релевантности `{0, 1, 2}`.
  * Алгоритм TF-IDF, косинусное сходство, `k = 3` и правило сортировки по убыванию оценки и возрастанию `item_id`.
  * Фильтр прав доступа перед выдачей.

## 4. Критерий принятия и критерий отрицательного результата
* **Гипотеза подтверждена, если:**
  1. Средний `NDCG@3` на `validation` вырос минимум на `+0.20` (итоговый `NDCG@3 >= 0.7000`).
  2. Средний `Recall@3` не ниже baseline (`>= 0.3611`), а качество на сегменте `literal` не ухудшилось (`>= 0.9073`).
  3. Доля карточек без допуска в выдаче равна `0`.
* **Гипотеза не подтверждена (отрицательный результат), если:**
  * прирост среднего `NDCG@3` оказался меньше `+0.10` (итоговый `NDCG@3 < 0.6000`), **или**
  * замена синонимов внесла ложные совпадения и ухудшила одну из защитных метрик (`Recall@3` или `literal NDCG@3`).
* **Ограничение проверки:** эксперимент проводится на замкнутом учебном наборе из `12` запросов; проверка реальной пользы для художников и режиссёров при поиске референсов остаётся отдельной задачей.
