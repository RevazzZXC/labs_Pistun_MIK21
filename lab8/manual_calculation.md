# Ручной расчёт метрик (`manual_calculation.md`)

## 1. Исходный запрос и разметка
Возьмём для примера запрос **`Q01` (`«неон дождь ночной город»`)** (опорный буквальный запрос по тематике ночного города с неоном и дождём).
В разметке для него есть три релевантные карточки:
* `V001` — оценка **`2`** (точное совпадение сцены и атмосферы)
* `V002` — оценка **`2`** (точное совпадение сцены и атмосферы)
* `V007` — оценка **`1`** (частичное совпадение: смежный световой мотив, но другая сцена)
* Все остальные карточки — оценка **`0`**.

Формулы из `metric_spec.md` (`k = 3`, позиции $i = 1, 2, 3$):
* $\text{gain}(\text{rel}) = 2^{\text{rel}} - 1$
* $\text{DCG@3} = \sum_{i=1}^{3} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}$
* $\text{NDCG@3} = \frac{\text{DCG@3}}{\text{IDCG@3}}$
* $\text{Recall@3} = \frac{\text{число найденных релевантных карточек в топ-3}}{\text{общее число релевантных карточек запроса}}$

---

## 2. Идеальный порядок выдачи (`[V001, V002, V007]`, оценки `2, 2, 1`)
* Переводим оценки в `gain`:
  * Позиция 1 (`rel = 2`): $2^2 - 1 = 3$, знаменатель $\log_2(1 + 1) = \log_2(2) = 1.0$ $\Rightarrow \frac{3}{1.0} = 3.0$
  * Позиция 2 (`rel = 2`): $2^2 - 1 = 3$, знаменатель $\log_2(2 + 1) = \log_2(3) \approx 1.58496$ $\Rightarrow \frac{3}{1.58496} \approx 1.89279$
  * Позиция 3 (`rel = 1`): $2^1 - 1 = 1$, знаменатель $\log_2(3 + 1) = \log_2(4) = 2.0$ $\Rightarrow \frac{1}{2.0} = 0.5$
* Суммируем полезность:
  $$\text{DCG@3} = 3.0 + 1.89279 + 0.5 = 5.39279$$
* Так как порядок наилучший из возможных, $\text{IDCG@3} = 5.39279$:
  $$\text{NDCG@3} = \frac{5.39279}{5.39279} = \mathbf{1.0000}$$
* В топ-3 попали все `3` релевантные карточки из `3` возможных:
  $$\text{Recall@3} = \frac{3}{3} = \mathbf{1.0000}$$

---

## 3. Фактический результат baseline для `Q01` (найдены `2` карточки с оценками `2, 2`, 3-я не попала в топ-3)
В твоём запуске `baseline.py` для `Q01` в топ-3 вошли две карточки с оценкой `2` (третья релевантная карточка в топ-3 не попала):
* Позиция 1 (`rel = 2`, $\text{gain} = 3$): $\frac{3}{\log_2(2)} = 3.0$
* Позиция 2 (`rel = 2`, $\text{gain} = 3$): $\frac{3}{\log_2(3)} \approx 1.89279$
* Позиция 3 (нет релевантной карточки, $\text{rel} = 0$, $\text{gain} = 0$): $0.0$
* Считаем метрики при $\text{IDCG@3} = 5.39279$:
  $$\text{DCG@3} = 3.0 + 1.89279 + 0.0 = 4.89279$$
  $$\text{NDCG@3} = \frac{4.89279}{5.39279} \approx \mathbf{0.9073}$$
  $$\text{Recall@3} = \frac{2}{3} \approx \mathbf{0.6667}$$
* **Сверка с кодом:** числа `0.9073` и `0.6667` полностью совпадают с выводом `baseline.py` (`results/validation_baseline_detail.json`).

---

## 4. Нарушение порядка (оценки в выдаче `1, 2, 2` вместо `2, 2, 1`)
Допустим, модель нашла те же три карточки (`Recall@3 = 3/3 = 1.0000`), но поставила карточку с оценкой `1` на первое место, а карточки с оценкой `2` — на второе и третье:
* Позиция 1 (`rel = 1`, $\text{gain} = 1$): $\frac{1}{\log_2(2)} = 1.0$
* Позиция 2 (`rel = 2`, $\text{gain} = 3$): $\frac{3}{\log_2(3)} \approx 1.89279$
* Позиция 3 (`rel = 2`, $\text{gain} = 3$): $\frac{3}{\log_2(4)} = 1.5$
* Считаем полезность:
  $$\text{DCG@3} = 1.0 + 1.89279 + 1.5 = 4.39279$$
  $$\text{NDCG@3} = \frac{4.39279}{5.39279} \approx \mathbf{0.8146}$$
* **Вывод:** `Recall@3` остался `1.0000` (нашли все карточки), но `NDCG@3` упал с `1.0000` до `0.8146`, потому что лучший референс оказался ниже первого места.

---

## 5. Пустая выдача (например, запрос `Q02` `«киберпанк ливень мегаполис»`, выдача `[]`)
* Ни одна карточка не выдана (`DCG@3 = 0.0`, найдено `0` из `3` релевантных):
  $$\text{NDCG@3} = \mathbf{0.0000}, \quad \text{Recall@3} = \mathbf{0.0000}$$

---

## 6. Зачем это проверяется отдельными тестами
Ручная проверка и отдельные тест-кейсы (идеальный порядок, неполная выдача, перепутанный порядок, пустая выдача) нужны, чтобы ошибка в формуле дисконта, нормировки или обработке пустого списка не пряталась за общим средним по всем запросам.
